# 常见的坑

## 拆原片
- **whisper 听歌会幻听**：对着歌曲可能输出完全不存在的句子。MV 有烧录歌词就用 `scan.py ocr`（macOS Vision）读画面；没有歌词条，就让用户给歌词文本，再靠 `align` 找段落。
- **镜头内暗切**：场景检测阈值 0.3 会漏掉暗场里的切换和闪白。`build_ref.py` 切完会用 0.2 再扫一遍，报出来就把那一镜缩短或挪起点。
- **拼接处削波**：两段歌接上，峰值可能超过 1。`build_ref.py` 已经加了 `alimiter 0.93`。
- 原片比 16:9 宽（2.39:1）时，每个镜头的 `cx` 要单独看：两人同框的镜头裁中间会切掉人。
- **黑场闪帧**：打斗、转场镜头里常有一两帧全黑（场景检测看不出），成片里是一下黑闪。`build_ref.py` 会按亮度报出来，挪起点躲开。叠化转场也要躲，H3 会把叠影当成画面内容。
- **快切**：原镜头只有 0.6–1.5 秒时，剪的时候能取长的就取长的；必须用的短镜头，H3 生成后用 `speed` 放慢。
- **macOS 隐私权限**：命令行读不了 `~/Downloads`、`~/Desktop`（Operation not permitted），请用户把文件拷进工程目录，别绕权限。

## 换脸
- **骨相跟着原演员走**：直接 swap，模型会贴着原脸的轮廓和五官位置改，用户一眼看出"像原片的人"。用 repaint 或 joint 解决。
- **打码要盖住五官，不要盖住头发和轮廓**：椭圆、像素块约 1/7 脸宽、边缘羽化。盖太大，它会连发型一起重画。
- **自动人脸检测不可靠**：Haar 对侧脸、低头、闭眼、拥抱、超大特写基本找不到，在 `box` 里手标。两人同框用 `hint` 挑人。
- **配饰要从一开始就带上**：先换脸后补眼镜要多跑一轮，还可能把眼镜加到别人脸上。写进 `cast.json` 的 `accessory`。
- **只有头发、看不到脸的帧**不要硬换，不写 `pose`，直接用原片帧。
- **模型重画整张图**：手臂没了、别人也变成主角的脸。用 `faces.py joint`，只贴回头部，其余保留原片像素。
- **Codex**：
  - 提示词放在 `-i` 后面会被当成图片路径吞掉 → 走 stdin。脚本已处理。
  - **满载**（"Selected model is at capacity"）可能持续几个小时，而且可能只有带图编辑这条路满载，换模型也没用。先看脚本打印的原因，满载就 `--wait 60` 挂着补，同时走退路（`keys.py zoom`、`first_only`），或换自建 HTTP 通道。跟用户说清是服务端容量问题，不是提示词或内容的问题。
  - 一次最多看 5 张图：脚本已按这个分配身份照。
- **用户自己做的帧**：裁成 16:9 放 `keys/user/NN_a.png`，`first_only: true`。

## H3
- **ref2va 不适合 1:1 复刻**：场景和人物会被重编，参考脸也换不上。用 fl2va。
- **长度**：H3 训练区间 124–362 帧，短于 124 会糊或抖。原镜头只有 40–60 帧也生成 124 帧，`finish.py` 再均匀重采样回去（动作会显得稍快，但首尾姿势跟原片对得上）。超过 362 帧的镜头 `h3_fl.py` 会停下，要拆开。
- **链路慢**：VPN 中继时 PNG 上传很慢，脚本已改成 JPEG q2。首次 SSH 握手可能要一分多钟。
- **任务丢失**：ComfyUI 重启后队列和历史都没了，脚本连续 3 次查不到就标记丢失，再 `run` 一次会重新入队。
- **人物自己张嘴说话**：H3 会同时生成声音和画面，特写里经常让人开口。管用的组合见 `prompts.md`：`sound` 写完全静默、"嘴一直闭着"放在描述最前面、`--steps 20`、还不行就 `take: "head"`。
- **远景小脸崩坏、眼镜变形**：8 步画不细小脸。改用 20 步，并在描述里写"脸清楚自然、跟首尾帧一致；眼镜细小"。
- **剧情理解错**：H3 只看画面，会自己"合理化"动作。写法见 `prompts.md`。我们自己也会理解错，写之前 `keys.py look NN --pad 2` 看整段。
- **相邻镜头的连戏**：上一镜造成的状态，下一镜 H3 不知道。下一镜的 `desc` 要把结果写进去，尾帧也要是同一个状态。
- **配饰闪烁**：脚本按 `accessory` 自动写"一直戴着、不闪烁、不变形"。
- **转场镜头会幻觉**：首尾两帧差别很大的镜头，H3 会编一个中间过程。要么换成更接近的两帧，要么 `first_only`，要么 `keep_orig`。
- **中间编出陌生人、跳场景**：跑 `qa_h3.py` 抓，不过就 `--redo`（自动换种子）。
- 拥抱、亲吻这类两张脸贴在一起的镜头最容易崩，留到最后单独处理。
- **`first_only` 的镜头动作是 H3 自己演的**，跟原片尾姿势对不上；但只要 `desc` 写清楚，观感往往够用。汇报时写明。

## 后期和交付
- **成片太大**：带颗粒的 1080p 用 crf 15 可能上 GB。最终编码 crf 26 + `-preset slow -tune film`，100% 放大基本看不出差别。
- **ffmpeg 写完文件不退出**：叠图片的输入要写 `-loop 1 -t <总长>`，输出加 `-shortest`。
- **字体**：脚本会按系统找中文字体，找不到就 `configure.py --font <路径>`。
- **pkill 别杀到自己**：`pkill -f` 的模式会匹配到正在跑的这条 shell 命令本身。先 `pgrep -fl` 看清楚，再按 PID 杀。
- **重做前留旧版**：`h3_fl.py run --redo NN` 会把旧的挪进 `_old/`；用户常会说"还是上一版好"。
- ffmpeg 在 shell 循环里会吃掉 stdin → 一律加 `-nostdin`。新版 ffmpeg 没有 `-vsync`，用 `-fps_mode`。
- macOS 没有 `timeout` 命令。
